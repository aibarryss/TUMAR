# Тестовый SOS без push

## Что выполнить в Supabase

Предыдущий SQL контактов уже должен быть выполнен. В том же проекте открыть SQL Editor → New query, вставить ВЕСЬ файл `supabase/migrations/202610190002_test_sos.sql` и нажать Run. Ожидается завершение без ошибки, обычно `Success. No rows returned`.

Миграция не удаляет пользователей, приглашения или связи. Добавляет таблицы тревог и получателей, небольшую служебную таблицу соответствия попыток событиям, закрытое представление данных и защищённые серверные функции. Служебная таблица нужна, чтобы повторные запросы никогда не превращались в новый SOS после завершения старого. Все записи создаются одной транзакцией. Прямой доступ из приложения к таблицам и представлению закрыт, RLS включён; доступ только через RPC вошедшего пользователя.

Триггер на существующей таблице связей завершает активный тест при отзыве контакта. Повторный запуск файла не удаляет данные. Тестовые файлы из tests/ не вставлять в облачный SQL Editor.

`.env` не менять. Перезапустить сервер Expo (`Ctrl+C`, затем `npm start`) и открыть приложение. Если экран не обновился — `npm start -- --clear`. Новая зависимость expo-crypto входит в поддерживаемые модули Expo Go; собственная сборка не нужна.

## Проверка на двух аккаунтах

1. У A должен быть принятый контакт B, который получает сигналы A.
2. После входа A видит главную. Нажать «Тестовый SOS» и подтвердить отправку. Ожидается экран события с пометкой «Тестовая тревога», получателем B, временем и статусом «Сервер принял SOS».
3. Войти B (можно на том же телефоне через «Аккаунт» → «Выйти из аккаунта»). На главной нажать «Проверить сигналы», открыть входящий сигнал и нажать «Подтвердить просмотр».
4. Войти A, нажать «Проверить сигналы» и открыть событие. Видно подтверждение B и время. Тест остаётся активным.
5. Нажать «Завершить тест». Видно время завершения; на главной событие исчезает из активных, можно начать новый тест.
6. Внешние карты открывают фиксированную демонстрационную точку в Семее. Геолокация телефона не запрашивается.

Обновление выполняется вручную и при возвращении приложения из фона. Push, постоянное слежение, история событий и автоматическое обновление через Realtime не подключены. Завершённый тест доступен на уже открытом экране, но архив на главной не добавлен.

## Проверка ошибок

- Без принятого контакта кнопки отправки нет; сервер также отклоняет запрос.
- Повторное нажатие во время загрузки заблокировано. Другой запрос при активном тесте возвращает то же событие.
- Закрыть проект в Expo Go и открыть снова: активный тест загружается с сервера.
- Проверить обрыв сети при отправке. До запроса на телефоне сохраняется идентификатор попытки отдельно для каждого аккаунта. При ошибке и перезапуске «Обновить» только проверяет результат; новый SOS автоматически не отправляется. «Повторить ту же попытку» требует явного подтверждения и использует тот же идентификатор.
- Запрос ограничен ожиданием 15 секунд; тайм-аут не означает, что сервер ничего не сохранил.
- Войти посторонним аккаунтом: он не видит чужую тревогу. Отправитель не может подтвердить просмотр, получатель не может завершить тест.
- Удалить связь A/B во время теста. У A открытое событие после обновления показывает «Тест завершён: связь удалена». B теряет доступ. Новый получатель A не получает доступ к старым событиям.
- Проверить длинный email, небольшой экран, системную кнопку «Назад» и переходы между главной, контактами и тревогой.

## Что проверено локально

`npm test` использует временный PostgreSQL (PGlite), не ваш Supabase. Проверяются создание и атомарная запись, сохранение и разрешение попыток, повторные запросы после завершения, ограничения ролей, одно активное событие, подтверждение, завершение, закрытие при удалении связи и отсутствие доступа нового контакта к старым событиям. Это последовательные проверки SQL и ограничений, не нагрузочный тест параллельных подключений.

TypeScript и Android-экспорт проверяются отдельно. Выполнение миграции в облаке, поведение Expo Go и ручные проверки выше подтверждаются на устройстве после настройки.
