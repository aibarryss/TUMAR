# Android push: проверка MVP

Дизайн и логика тестового SOS сохранены. Добавлены регистрация Android-телефона, серверная очередь отправки и переход к существующему экрану тревоги из уведомления. Нажатие на уведомление само по себе не подтверждает просмотр.

## Что уже настроено

- Firebase: `tumar-1f480`; Android package: `kz.tumar.app`.
- EAS: `@aibaniii/tumar`, профиль `preview`, внутренняя установка APK.
- Firebase service account загружен в EAS FCM V1. Приватного ключа в исходниках и APK нет.
- В EAS preview переданы только публичные URL и ключ Supabase. Серверные секреты остаются в Supabase.
- Миграция `supabase/migrations/202610200001_android_push.sql` добавляет закрытые таблицы устройств/заданий и функции регистрации и обработки очереди. Старые данные не удаляются.
- `send-sos-push` развёрнут в Supabase. Случайный секрет вызова хранится в Edge Function Secrets и Vault.
- `supabase/setup-push-scheduler.sql` включает немедленный асинхронный запуск после записи задания и резервную проверку раз в минуту.

## Самая простая проверка

1. Установить APK на Android, открыть TUMAR, войти **аккаунтом получателя**, разрешить уведомления. На главной дождаться текста «Уведомления включены на этом телефоне».
2. У аккаунта отправителя должен быть привязан этот получатель. Отправитель может пользоваться Expo Go: нужен другой аккаунт, отдельный второй телефон не обязателен — Expo Go и установленный TUMAR могут работать на одном Android.
3. Свернуть установленный TUMAR. В аккаунте отправителя отправить новый тестовый SOS. Если есть предыдущий активный тест, сначала завершить его.
4. На Android получателя должно появиться уведомление «TUMAR · Тестовый SOS». Нажать его: открывается правильный сигнал. Нажать «Подтвердить просмотр» и проверить результат у отправителя кнопкой «Проверить состояние».

APK работает самостоятельно: компьютер, Metro, одна Wi-Fi-сеть и Expo Go для получателя не нужны. Интернет нужен обоим аккаунтам.

## Дополнительные проверки

- Повторить с приложением открытым: уведомление показывается, список перечитывается.
- Убрать приложение из списка последних и проверить открытие по push. Это отличается от «Принудительно остановить» в системных настройках Android.
- Запретить уведомления: объяснение появляется на главной, ручная проверка остаётся доступной.
- Выйти и войти другим аккаунтом на этом же телефоне: устройство отвязывается от прежнего пользователя. Старое уведомление не должно открывать чужое событие.
- Удалить доверенную связь: новые попытки отправки по ней прекращаются, доступ к событию перепроверяется сервером.
- Сервис push может принять уведомление, но это не доказывает показ на телефоне. Человеческое подтверждение хранится отдельно.

Очередь делает до трёх попыток при временных ошибках, проверяет квитанции Expo и удаляет недействительные токены. Из-за неопределённого сетевого результата повторная внешняя отправка иногда возможна; сама тревога и задание не дублируются. Ручная проверка сохранена.

## Проверки разработки

`npm run typecheck`, `npm test`, Android-экспорт. Доставка на физическом телефоне проверяется отдельно по сценарию выше. Установка/получение push пока не подтверждены пользователем.
